# 四个 λ 离线选参：受限模拟

作者已确认采用“四个 λ 离线选参”。在线调度器和 `pkg/schedpolicy/score.go` 均未修改。新增实验直接调用该评分函数，用四项指标离线选择三个在线评分参数；结果不冒充 NJ-k1 真机运行或完整 Tide 故障恢复实验。

## 结果与建议

第一版建议的目标偏好为 λ=(0.25,0.25,0.25,0.25)，对应本轮校准网格选择的在线评分参数为 **(w_u,w_l,w_d)=(0,0.9,0.1)**。零资源评分权重不关闭原有容量可行性过滤。这个组合是本实验的候选配置，未部署到运行时，也未追认为历史实验配置。

独立测试集、对全部场景等权平均：

| 指标 | 原等权评分 | 原占位候选 (.45,.35,.20) | 校准选择 (0,.9,.1) |
|---|---:|---:|---:|
| 窗口 deadline goodput / offered rate | 80.2070% | 79.9837% | 87.1284% |
| 断网窗口提交请求按时完成率 | 77.2083% | 75.4500% | 80.7174% |
| CPU/内存执行占用（模型） | 10.0731% | 10.0655% | 10.0715% |
| 返回请求平均时延 | 145.1504 ms | 142.4364 ms | 105.9016 ms |
| 每次运行 P95 的场景均值 | 219.5250 ms | 219.9694 ms | 177.9528 ms |

相对原等权评分，平均时延约降低 27.0%，归一化窗口 goodput 提高约 6.92 个百分点，断网窗口按时完成率提高约 3.51 个百分点；**利用率没有改善证据**。条件时延只包含收到响应的请求，必须结合丢失/拒绝/超期数理解。

六种事先指定的目标偏好都选择相同参数，并不说明四项目标完全等价：校准网格中吞吐与时延最优点为 (0,.9,.1)，韧性单项最高点为 (.1,.7,.2)，利用率单项最高点为 (0,.5,.5)；这三个单项位置是事后诊断，没有用于重新设定 λ。利用率的校准均值范围只有约 9.914%–10.030%，影响很小。

48 次 λ 单坐标乘 0.7/1.3 并归一化的敏感性检查中，46 次仍选择 (0,.9,.1)；韧性偏好下增加 λ₂ 或降低 λ₄ 的两次选择 (.1,.9,0)。这不等于“在线评分参数 ±30% 扰动使 goodput 变化小于 5%”。

按事后诊断阈值“等权校准目标距最好值不超过 0.005”，近优网格点为 (0,.8,.2)、(0,.9,.1)、(.1,.7,.2)、(.1,.8,.1)、(.1,.9,0)、(.2,.7,.1)。阈值只描述这批数据，不是预先证明的稳健区间；不能把各坐标的最小/最大值组合成全都有效的长方体区域。

等权目标下，固定校准选择的测试分数为 0.312416；测试集事后最佳网格分数为 0.318861。保留这个差距，没有用测试集替换校准选择。

## 精确模型与统计口径

- 时间刻度 0.1 ms，发送窗口 [0,30 s)，远端 gate 在 [10,20 s) 不可用。两本地、一远端串行执行器；节点 CPU 为 4/6/8，内存预算为 1024/1536/2048 MiB，每个执行器使用 2 CPU 配额。
- 网络响应预算低档 2/12/35 ms，高档 10/40/100 ms。网络不占用串行执行器，不代表实际测量或带宽模型。感知/执行能力均预设合格，R_cap=1 是固定结构描述。
- 三种工作负载的基础尺度是已有 `weights-02/calibration.json` 中的内核 p95：CPU 21.283347 ms、内存 78.898112 ms、I/O 59.614709 ms。节点执行因子依次为 (1.3,.9,1.15)、(.9,1.2,.85)、(.7,.85,1.1)。请求大小系数取 0.75–1.25、0.01 步长，类型等概率；内存令牌为 64/256/32 MiB。这些因子和内存数值是声明的模型输入，不是新硬件测量。
- 预计服务时间为基础尺度×节点因子×大小，再向上取整到刻度。实际模拟服务时间为预计值×同一请求共享的 U[0.8,1.2) 误差系数再向上取整；真实请求结果不由绘图代码生成。
- 调度只看预计队尾和当前已知连通性，不预知未来断网或实际服务时间。实际 FIFO 队尾独立维护；可观察到执行器已经空闲时，预计队尾重置。失联请求不会回滚已经排队的计算，计算仍计入资源占用；不重试、不迁移。
- 远端请求从提交到预计的实际返回时刻只要跨过断网起点，其响应即丢失；在断网起点返回算丢失，在恢复时刻开始的新提交可以选远端。收到响应且响应时间不晚于自身截止期才算按时完成，截止期统一为 200 ms。恰好在 30 秒返回不计入窗口 goodput，但计入 cohort/drain。
- Θ̃=窗口内按时响应数/发送窗口全部请求数，即窗口 goodput 除以本轨迹的实际 offered cohort rate。R_srv=断网窗口提交且最终按时完成数/该窗口全部提交数。后者允许本地任务在恢复后、但仍在自身截止期内完成。
- Ũ 为 CPU 与内存占用积分各除以对应整窗口总容量积分后取平均；仅累计实际模拟执行区间与窗口的交集，包含响应丢失的计算。它是受限模型的执行占用，不是原生 Tide 的固定 Stub 预留、Linux CPU 利用率或 RSS。
- L̃=min(1, 返回请求平均响应时延/200 ms)，没有返回请求时记 1。原始未截断时延、P95 和全部结果计数另存。丢失请求不作为“零时延成功”加入均值。
- J=(λ₁Θ̃+λ₂R_srv+λ₃Ũ−λ₄L̃)/Σλ。每个指标使用固定单位与尺度，不按参数点重新缩放，也不按本批最小/最大结果归一化。

## 固定矩阵与选择程序

3 档请求速率 10/30/60 × 2 到达模式 × 2 网络档 × 3 校准/3 测试种子 × 68 个评分候选 = 4896 次运行。36 条请求轨迹被两种网络档及全部评分候选重复使用；共 4,882,536 个决策。

steady 使用 Poisson 到达；burst 每 5 秒交替使用 0.5/1.5 倍基准速率，30 秒内包含 3 个周期。随机种子公式记录在 `cmd/revision-calibrate/main.go`，校准/测试种子集合不相交。所有请求输入保存在 `inputs.json`，无需重新采样就能核验。

候选包含 66 个 0.1 步长单形网格点、等权点及原占位候选。六种 λ 为：等权 (.25,.25,.25,.25)；旧草稿比例 (1,1,.5,1)；吞吐偏重 (.55,.15,.1,.2)；韧性偏重 (.15,.55,.1,.2)；利用率偏重 (.15,.15,.55,.15)；时延偏重 (.15,.15,.1,.6)。比例进入目标时归一化。旧草稿比例仅作为本次新增实验中的偏好候选，不证明历史使用过。

只最大化校准集上平衡场景的平均 J；数值差在 1e-12 内时优先靠近等权的评分参数，再按网格顺序。选择冻结后报告测试集。没有对 λ 自身做“最大化各自分数”的无意义调参。图中的 t 区间以 3 个独立种子批次为重复单位，每批先平均 12 个场景，df=2；它描述模拟输入变化，不是硬件测量不确定性。

## 复现与交付

在 `code/Tide` 下：

```sh
env GOMODCACHE=/tmp/tmc-go-mod GOCACHE=/tmp/tmc-go-cache go test ./cmd/revision-calibrate ./pkg/schedpolicy ./cmd/revision-sensitivity
env GOMODCACHE=/tmp/tmc-go-mod GOCACHE=/tmp/tmc-go-cache go run ./cmd/revision-calibrate -out /tmp/objective-replay-new
python3 scripts/revision/verify_objective.py --root /tmp/objective-replay-new
python3 scripts/revision/plot_objective.py --root results-objective-20261005 --paper-figs ../../revision-figs/evaluation
```

输出目录必须不存在或为空。Go 只需标准库和仓库已有评分函数；绘图需要 numpy/matplotlib。`scripts/objective_calibration.ipynb` 内嵌图表数据和绘图程序，运行时将 PDF/PNG 输出到当前目录的 `objective-calibration-exports/`，不读取外部图片。

`inputs.json`、`decisions.csv.gz`、`summary.jsonl` 是原始证据，`selection.json` 保存六种偏好的冻结选择，`lambda_sensitivity.json` 保存 48 次扰动选择及其测试指标，`verification.json` 记录独立 Python 全量重放。`heldout_summary.csv`、`per_scenario.csv`、`plot_data.json` 用于查看和绘图。

先前 `results-objective-20261005-pilot/` 保留为阶段记录：其 λ 扰动文件的事后测试最优分数字段曾误写 0；正式目录已经修正，并加强独立核验。两个目录的逐请求决策和运行汇总应完全一致，正式结论仅引用本目录。
