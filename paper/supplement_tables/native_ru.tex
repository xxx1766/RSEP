\section{Native Endpoint Outages and Application Resource Occupancy}
\label{sec:supp-native-ru}
\noindent\textbf{Datasets and matched inventory.}
Two Nanjing KVM hosts, NJ-k2 (local/origin) and NJ-k1 (cloud), each retain one prestarted serial Go PAIX worker. Each worker has a two-vCPU quota, CPU set 0--1 and a 512-MiB memory limit; newly launched control/driver processes use vCPUs 8--15. Guest logical CPUs do not imply exclusive physical cores. The same worker image, kernels, allocated inventory and limits apply to native Tide and native cloud-only. The CPU kernel processes 65,536 bytes for 100 iterations; the memory-access kernel processes 16,777,216 bytes for four iterations. Both perform real work and return independently checked output checksums and processed-byte counts. Go parallelism is one per worker (\texttt{GOMAXPROCS(1)}); a two-vCPU budget does not imply two-way kernel parallelism. Five warmups and twenty measured service samples per node/kernel determine the frozen inverse-median kernel-service capacity and per-node ceiling-P95 execution estimates. Integer-rounded rates target nominal 30\%/80\% of aggregate kernel-service capacity; native admission, PAIX and return overhead are excluded from that reference.

\noindent\textbf{Baselines and comparability.}
Native cloud-only deliberately leaves its allocated local worker unused. Its submission helper retains the native routine envelope, C4 eligibility check, cloud execution handler and result-wait protocol, but directly submits to the cloud queue, bypassing Tide's origin-side deadline feasibility screening and placement/scoring. This is a comparison of integrated placement and admission policies under matched allocated application budgets. It does not isolate local capacity alone or establish equal whole-system overhead. Cloud-side compatible work may queue beyond its deadline; no request is removed from a denominator because it fails or returns late.

\noindent\textbf{Outage protocol and outcomes.}
Twenty R treatments offer the CPU kernel for 30~s, with approximately 10-s connected, unavailable and recovered periods, followed by 8~s observation. Both owned native gRPC endpoints reject cross-node events while gated; HTTP measurement/control remains reachable. This is event-endpoint unavailability, not a physical network partition. Stable outage starts after both enable acknowledgements and ends at the first release invocation. Both transition intervals remain separate cohorts. Cohorts use actual server ingress submission timestamps on the origin monotonic clock (driver-start fallback, when needed, is explicitly retained); the 500-ms deadline uses client round-trip time. Thus an outage-arrival cohort is not a count of work completed entirely while the gate remains closed. Raw records distinguish failed, timed-out, correct but late and timely returns. In the count tables, No valid aggregates submission/native errors, invalid outputs and requests without a valid return within the observation timeout. Native result-observation timeouts are 5~s for R and 30~s for U, with client transport timeouts five seconds longer. Observation timeout does not cancel admitted execution. Recovery concerns new arrivals after release, without retry, migration or in-flight recovery guarantees.

\noindent\textbf{Resource protocol and model correspondence.}
Forty U treatments cover both kernels and reference loads. Each has fixed 5-s warm-idle, 20-s offered-load and 25-s post-offer windows. The total resource window is 50~s. Cumulative CPU counters come from distinct owned leaf cgroups; 100-ms process PSS samples represent resident application memory, including warm residency. Charged cgroup memory is reported separately. Fixed per-tier fractions use two CPUs and 512~MiB. The predeclared index is $U_{\rm obs}=\tfrac12(C_L+M_L)+\tfrac12(C_C+M_C)$; its range is a sum index, not a percentage bounded by one. Worker PID/start-time, cgroup identity/membership, actual CPU quota, CPU set and memory limit are checked throughout each window. Missing data are not replaced by zero; gaps/read spans above 500~ms fail resource qualification. CPU counters and PSS are interpolated at clipped boundaries, with trapezoidal PSS integration. Separate host-monotonic windows use bracketing minimum-RTT clock probes and affine offset interpolation; uncertainty and drift bounds must each remain within 10~ms. Unobserved clock jumps are not ruled out. Resource costs divide CPU seconds or integrated PSS byte-seconds by valid/timely returns inside the same fixed window. Later outcomes remain recorded but do not enter that window's cost denominator.

For these compute-only requests, sensing/actuation predicates are empty and the originating node's total CPU capability meets every request: structural $R_{\rm cap}=1$ under both policies. This objective is not improved by the policy comparison. Measured $R_{\rm srv}$ instead denotes outage-arrival deadline yield over all offers. Model $U$ uses remaining-capacity state, including reservation-ledger CPU capacity, and CoW--CoT tier weight $\alpha_{\rm full}=0.5$ as a modeling convention. Actual CPU/PSS $U_{\rm obs}$ is an operational analogue with fixed tier weight $1/2$; it neither estimates $\alpha_{\rm full}$ nor validates full-model resource management. Larger occupancy alone is not an efficiency benefit. PSS does not establish peak working-set demand or prove memory-bound execution. Earlier single-host controlled-executor native checks and the separate HTTP fault adapter retain their original scope.

\noindent\textbf{Reporting.}
Five paired randomized blocks retain all twelve treatment cells (four R and eight U). Cohort goodput divides all timely cohort returns by the 30-s R or 20-s U arrival window, including timely returns collected just after offering stops; fixed-window resource costs instead count returns only inside their stated window. Tables report run-level means $\pm$ pointwise 95\% intervals, $2.776s/\sqrt{5}$ using $t(4)$, without pooling requests. Paired contrasts are Tide minus cloud-only, with the interval computed from five within-block differences. Intervals are not clipped at physical bounds and are not simultaneous. An undefined per-completion cost, including zero timely completions, is shown as -- ($n/5$ available); no partial-run mean is substituted for a five-run result. Table labels use Cloud for native cloud-only, Mem for memory access, and load/rate for nominal percentage/actual requests per second. CPU/PSS costs exclude shared containerd and native control processes; diagnostic control observations remain in the archived samples.

The retained formal campaign contains 58,800 offers, 44,762 valid returns and 17,069 timely returns. All 60 individual run rows follow below.
